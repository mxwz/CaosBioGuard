# 硬件选型、组装部署与 APK 实施方案

本文面向 CaosBioGuard 后续门禁一体机、边缘端、服务器和手机端建设，提供通用选型、接线、部署和 APK 路线。具体品牌型号可在采购前根据预算、门体和安装环境复核。

## 1. 总体架构

推荐采用“边缘识别 + 本地/云端管理 + 多端访问”的结构：

1. 边缘门禁机负责采集、活体、模板比对、门锁控制和离线缓存。
2. 本地服务器或 Web 容器负责管理、审计、记录、模板版本和设备状态。
3. 手机/PWA/小程序负责用户自助查询、管理员审批和远程查看。
4. 公网模式通过 HTTPS、安全组、Token、HMAC 和可选 IP 白名单保护。
5. 离线模式下边缘端继续工作，网络恢复后通过 outbox 同步。

## 2. 边缘主机选型

### 方案 A：x86 迷你主机，当前软件兼容性最好

适合：Windows 10/11、PySide6、摄像头、PyInstaller、快速验证。

建议配置：

- CPU：Intel N100/N150 或更新 x86 处理器
- 内存：8 GB 起步
- 存储：128 GB SSD
- 接口：USB、HDMI、RJ45，最好支持 RS485/串口
- 系统：Windows 10/11 或 Linux x64

优点：PySide6、InsightFace、摄像头和打包流程最容易复用。

### 方案 B：RK3588 ARM 边缘主机，量产硬件推荐

适合：Android/Linux ARM64、NPU、低功耗门禁一体机。

建议配置：

- CPU：RK3588/RK3588S
- 内存：4–8 GB
- 存储：32–128 GB eMMC/SSD
- 系统：Ubuntu ARM64、Android、Buildroot 或厂商 BSP
- 接口：MIPI/USB 摄像头、GPIO、UART、RS485、继电器接口

优点：硬件扩展和 NPU 能力强，适合最终设备；缺点是系统适配和 SDK 桥接工作量更高。

### 方案 C：RK3566/RK3568，低配版

适合：单模态或少量模态、轻量门禁。

建议配置：

- 内存：2–4 GB
- 存储：16–64 GB
- 适合运行轻量模型、厂商 SDK、本地缓存和基础 UI

不建议在 2GB 设备上同时运行完整多模态、MySQL 和重型人脸模型。

## 3. 摄像头与活体设备

### 开发阶段

- 普通 1080P USB UVC 摄像头即可。

### 生产阶段

按安全等级选择：

1. RGB 摄像头：成本最低，依赖软件 PAD。
2. RGB + NIR 双目：可增强照片、屏幕攻击防护。
3. RGB + Depth/3D 结构光/ToF：适合高安全等级。
4. 带厂商活体 SDK 的门禁摄像头：可直接输出活体结果和模板。

软件启发式活体不能替代专用 PAD、双目或 3D 防伪设备。

## 4. 门锁与执行机构

### 电磁锁

适合办公室、社区单元门、防火门等常见场景。

特点：

- 通电上锁，断电释放；
- 稳定性高，门体适配简单；
- 需要配合门磁、UPS 和消防联动策略。

### 电插锁

适合玻璃门、双开门等需要隐藏式锁体的场景。

### 阴极锁/电控锁扣

适合部分木门、金属门，需要确认门体和机械结构。

### 继电器

选择带光耦隔离、干接点输出的串口继电器、网络继电器或 GPIO 继电器。要求：

- 支持开门、关门命令；
- 支持状态反馈；
- 支持自动重锁；
- 与门锁电压和电流匹配；
- 失败时可重试并报警。

## 5. 其它必备硬件

| 硬件 | 作用 |
|---|---|
| 门磁传感器 | 检测门是否关闭、是否被强行打开 |
| 出门按钮 | 室内人员合法出门 |
| 外部读卡器 | 支持刷卡、Wiegand 或其它备用识别 |
| 报警器 | 强行开门、重锁失败、篡改设备时报警 |
| 防拆开关 | 设备外壳被打开时触发告警 |
| UPS/备用电源 | 断电期间记录事件并执行安全策略 |
| 触摸屏外壳 | 8/10 英寸金属门禁机外壳，支持壁挂或嵌入式安装 |

## 6. 推荐接线逻辑

典型连接：

1. 边缘主机通过 USB 连接摄像头。
2. 主机通过 UART/RS485/网络连接继电器。
3. 继电器干接点控制门锁电源。
4. 门磁信号接入 GPIO、串口 IO 模块或控制器输入。
5. 出门按钮接入控制器输入。
6. 报警器接入继电器或专用报警输出。
7. 外部读卡器通过 Wiegand、RS485 或网络接入。
8. 所有低压控制线与强电线路分离，接线端子标注编号。

安全要求：

- 软件默认使用仿真继电器，切到真实硬件前必须确认命令和接线。
- 首次测试应断开门锁或使用测试电源，避免误动作。
- 自动重锁时间需要结合门体和通行速度设置。
- 断电策略必须明确：消防场景通常要求断电释放，高安全场景可能需要备用电源维持。

## 7. 服务器配置建议

### 2C2G 服务器

可以运行：

- Web 管理端
- Docker 容器
- 轻量数据库
- 设备状态和记录同步
- 反向代理

不建议在该服务器上执行重型模型构建、Docker build 或完整人脸推理。建议：

- 边缘端负责识别；
- 服务器只做管理和存储；
- MySQL 限制容器内部访问；
- 增加 swap；
- 定期备份 `dd/`、模板库和配置。

### 推荐服务器

- 4C8G 起步
- 40GB SSD
- 支持 Docker
- 可配置 HTTPS 反向代理
- 安全组仅开放必要端口

## 8. 端口与网络

默认 Web 端口建议使用：

- `6100`

可按需修改。公网部署时：

- 使用 443 接入 HTTPS；
- 反向代理到内部 `127.0.0.1:6100`；
- MySQL 不暴露公网；
- 可选 IP 白名单；
- 云安全组优先于应用内限制。

## 9. APK 实施方案

PySide6 不能直接生成 Android APK。推荐使用 Capacitor 包装现有 PWA。

### 必要环境

- Node.js / npm
- JDK
- Android Studio
- Android SDK
- Gradle
- Capacitor

### 实施步骤

1. 稳定现有 PWA 页面和移动端 API。
2. 适配移动端布局、摄像头、麦克风、文件上传和权限。
3. 安装 Capacitor 并创建 Android 工程。
4. 配置 API 地址、HTTPS、权限和应用图标。
5. 使用 Android Studio 构建 debug APK。
6. 真机测试后生成 release APK/AAB。
7. 再考虑应用市场或内部分发。

Kivy 或 BeeWare 不能复用现有 PySide6 UI，需要重写，因此仅作为备选，不作为当前推荐路线。

## 10. 验收清单

硬件验收应确认：

- 摄像头、触摸屏、边缘主机可长期稳定运行；
- 活体检测和识别结果可审计；
- 继电器开门、自动重锁、重锁失败报警正常；
- 门磁、出门按钮、外部读卡器、报警器均有效；
- 离线模式可继续识别并缓存事件；
- 网络恢复后同步无重复、无丢失；
- 管理员锁定、模板回退、注销封存可正常使用；
- 设备断电、重启、断网、串口断开后可恢复；
- 所有真实密钥均从环境变量或本机安全配置注入。
