# 硬件端设计说明

## 1. 总体结构

```text
┌──────────────────────────────────────────────────────────────┐
│                    边缘终端主机 / Edge Host                   │
│  PySide6 Kiosk + biometrics + local DB + sync outbox         │
└───────────┬───────────────┬────────────────┬─────────────────┘
            │ USB/CSI       │ USB/UART       │ TCP/HTTPS
            ▼               ▼                ▼
      人脸摄像头       多模态采集器       中心服务/移动端
      麦克风           指纹/虹膜等        Web/PWA/小程序
            │
            │ 隔离 I/O / 继电器板
            ▼
┌──────────────┬──────────────┬──────────────┬─────────────────┐
│ 电锁/道闸    │ 门磁         │ 出门按钮      │ 声光报警器       │
└──────────────┴──────────────┴──────────────┴─────────────────┘
            ▲
            │ 外部读卡器：Wiegand26 / RS485 / 厂商 SDK
```

软件入口为 `hardware/`：

| 模块 | 职责 |
|---|---|
| `hardware/types.py` | 设备状态、硬件事件数据结构 |
| `hardware/controllers.py` | 继电器抽象、仿真器、串口继电器、Wiegand 编码 |
| `hardware/manager.py` | 门锁、门磁、出门按钮、报警器、外部读卡器统一管理 |
| `sideUI/kiosk/app.py` | 人脸或多模态识别通过后调用硬件解锁 |

## 2. 典型设备清单

| 类别 | 建议 | 说明 |
|---|---|---|
| 边缘主机 | x86 小主机、RK3588、Jetson Orin Nano 等 | 至少保留 2 核 CPU、4GB 内存和 8GB 本地存储 |
| 人脸摄像头 | 1080P、宽动态、低照度 | 门禁场景建议支持红外补光或双目结构光 |
| 麦克风 | 全向/定向麦克风 | 用于声纹，噪声环境需做降噪和回声处理 |
| 指纹模块 | USB/UART 指纹仪 | 真实精度需接入厂商 SDK 和真实人员数据评估 |
| 虹膜/视网膜 | 专用红外采集器 | 当前软件仅提供接口与离线链路，不等同真实设备验收 |
| 掌纹/静脉 | 掌静脉/掌纹模组 | 通常需要厂商 SDK、授权和固定安装距离 |
| 电锁 | 磁力锁、电插锁、阴极锁 | 根据消防要求选择断电开锁或断电上锁 |
| 继电器 | 带光耦隔离的串口/USB 继电器 | 不允许把电锁直接接到主机 GPIO |
| 门磁 | 常开/常闭干接点 | 用于判断门是否真实闭合 |
| 出门按钮 | 干接点按钮 | 内部人员出门触发解锁 |
| 报警器 | 声光报警器 | 陌生人、强拆、长时间未关门时触发 |
| 电源 | 独立 12V/24V 电源 | 主机和锁控电源分开设计，共地按现场规范处理 |

## 3. 配置示例

```ini
[Hardware]
enabled=true
mode=simulator
serial_port=COM3
baudrate=9600
open_command=A0 01 01 A2
close_command=A0 01 00 A1
unlock_duration=3
alarm_duration=30
reader_protocol=wiegand26
lock_name=door-lock
```

- `mode=simulator`：无硬件时使用内存仿真器，适合开发、测试和演示。
- `mode=serial`：通过 `pyserial` 向继电器发送配置字节，不绑定固定厂商。
- 命令支持 `A0 01 02`、`A00102`、`0xA0,0x01` 三种常见写法。
- 识别成功后，Kiosk 按冷却时间调用 `HardwareManager.unlock()`，避免连续帧重复触发。

## 4. 串口继电器适配

不同厂商的继电器协议不同，接入时需要确认：

1. 串口号和波特率，例如 `COM3`、`/dev/ttyUSB0`、`9600`；
2. 打开/关闭继电器的十六进制命令；
3. 继电器是高电平脉冲还是低电平脉冲；
4. 脉冲时间是否由继电器板内部维护；
5. 板卡是否带光耦隔离和防浪涌保护。

当前 `SerialRelay` 只负责建立串口并发送字节，不假定校验和、通道号或厂商私有协议。替换为真实板卡时，优先在测试环境用示波器或继电器指示灯验证命令。

## 5. Wiegand 与外部读卡器

`WiegandEncoder` 提供 26 位 Wiegand 数据编码：

- 1 位偶校验；
- 8 位 facility code；
- 16 位 card number；
- 1 位奇校验。

编码结果只输出数据位和脉冲间隔，具体 D0/D1 GPIO 驱动需根据边缘主机平台接入 `libgpiod`、厂商 SDK 或独立 Wiegand 转换器。外部读卡器读到卡号后，应再与本地/中心人员权限做二次校验，不能只凭卡号开门。

## 6. 安全与接线要求

- 电锁、报警器和主机必须使用经过现场认证的电源与保护器件。
- 继电器和主控之间需要光耦隔离；感性负载应续流保护。
- 强电、弱电、锁控线分槽走线，避免摄像头和采集器受到干扰。
- 消防通道优先满足本地消防规范，不能由软件阻断紧急疏散。
- 公网场景下，硬件控制接口不直接暴露，只允许边缘本地服务调用。
- 所有开门、拒绝、报警、出门按钮、门磁状态都应写入事件库。
- 默认管理 token、默认 HMAC secret、空串口命令不得用于生产。

## 7. 健康检查与故障处理

`HardwareManager.health()` 输出门锁、门磁、出门按钮、报警器、外部读卡器状态。建议处理规则：

| 事件 | 建议动作 |
|---|---|
| 识别通过 | 继电器脉冲开门，到期自动回锁 |
| 出门按钮按下 | 本地触发开门并记录事件 |
| 门长时间未关 | 提示并触发声光报警 |
| 继电器串口不可用 | 降级为只读识别，记录硬件错误 |
| 外部读卡器异常 | 保留人脸/其他模态，不允许匿名开门 |
| 防拆/强制开门 | 触发报警并上传高优先级事件 |

## 8. 当前边界

当前仓库已完成硬件抽象、仿真器、通用串口发送、Kiosk 解锁调用和健康数据结构，但尚未针对某个具体厂商板卡做真机验收。真实项目落地前，需要补充：

- 设备型号、接线图、串口协议和继电器命令；
- 真实人员样本与 FAR/FRR/EER 指标；
- 长时间压力测试、断电恢复测试、消防联动测试；
- 现场防雷、防浪涌、备用电源和安装维护规范。
