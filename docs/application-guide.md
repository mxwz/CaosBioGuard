# 应用说明

## 1. 产品定位

CaosBioGuard 是面向工厂、园区、社区、实验室和小型办公场景的多生物识别考勤与门禁系统。系统覆盖边缘终端、Web 管理后台、PWA 手机端和微信小程序，支持离线本地识别、在线统一管理、云边同步和硬件门锁控制。

当前软件包含 9 类识别模态：

- 人脸
- 声纹
- 指纹
- 虹膜
- 掌纹
- 静脉
- 步态
- 视网膜
- 签名

其中人脸基于 InsightFace/ONNX Runtime；非人脸模态已完成离线算法接口、模板存储和合成数据链路验证。真实设备精度仍需接入对应采集器、厂商 SDK 和现场人员数据后评估。

## 2. 角色与权限

| 角色 | 入口 | 主要能力 |
|---|---|---|
| 管理员 | Kiosk 管理页、Web 后台、小程序管理员模式 | 人员管理、模板注册、设备状态、记录审计、主题配置、同步触发、硬件健康检查 |
| 员工/用户 | Kiosk 识别页、PWA、小程序用户模式 | 身份识别、考勤记录、个人模板、个人记录查询 |
| 边缘设备 | Kiosk 本地服务 | 本地推理、模板匹配、活体检测、outbox 缓存、继电器控制、报警联动 |

管理页默认隐藏，需要管理员验证后才能进入；普通识别、注册入口和记录查询不暴露底层系统设置。

## 3. 边缘 Kiosk 页面

边缘端使用 PySide6 Tab 化页面，不再使用旧的弹窗堆叠式设置。

| Tab | 页面 | 用途 |
|---|---|---|
| 识别 | 实时人脸/门禁页 | 摄像头预览、人脸框、识别结果、活体分数、开门状态 |
| 注册 | 人员人脸采集 | 采集人脸、生成模板、写入本地模板库 |
| 多模态 | 9 类生物特征 | 查看模态能力、注册/生成多模态模板、查看硬件建议 |
| 记录 | 考勤与门禁事件 | 通过、拒绝、陌生人、活体、报警和开门记录 |
| 管理 | 管理员页 | 主题、人员、模板、同步、设备和维护操作 |

顶栏提供引擎、摄像头、云边状态和主题切换；导航底部显示设备编号和版本。界面采用深色高科技风格，可在主题管理中切换内置主题。

## 4. 典型业务流程

### 4.1 首次启动

1. 重建或激活虚拟环境：`python -m venv .venv`。
2. 安装依赖：`pip install -r requirements-edge.txt`。
3. 确认 `buffalo_l` 模型位于本地模型目录，避免启动时联网下载。
4. 复制配置模板并按场景选择 `[Deployment]` 参数。
5. 无硬件时保持 `[Hardware] mode=simulator`。
6. 启动 Kiosk：`python -m sideUI.kiosk.app`。
7. 运行 `python deployment.py` 检查部署配置是否有错误。

### 4.2 人脸识别开门

1. 摄像头采集视频帧。
2. 人脸引擎检测并对齐人脸。
3. 质量门控过滤模糊、过小、角度过大的图像。
4. 生成 512 维 embedding 并与本地模板匹配。
5. 活体检测根据 `strict/degraded/off` 策略给出通过或拒绝结果。
6. 识别通过后写入事件并调用 `HardwareManager.unlock()`。
7. 继电器按配置脉冲开门，到期自动回锁。

### 4.3 多模态注册

1. 管理员创建或选择人员。
2. 人脸通过摄像头采集；声纹、签名等可通过对应采集页面生成。
3. 指纹、虹膜、掌纹、静脉、视网膜等真实硬件模态需接入厂商 SDK。
4. 模板经统一存储层加密保存；缺少加密依赖时会明确告警并降级。
5. 注册结果同步到本地仓库，在线分离模式下进入同步 outbox。

### 4.4 离线工作与恢复

- 离线模式下，识别、模板匹配、事件记录和仿真/本地硬件控制继续运行。
- 事件写入本地 SQLite outbox，不依赖中心服务实时可用。
- 网络恢复后，系统按幂等键补传，重复事件不会重复入库。
- 分离模式下，中心库仍为权威源，边缘只做缓存和补传。

### 4.5 Web/PWA/小程序

- Web 后台提供人员、多模态、考勤、设备和移动端 API。
- PWA 文件位于 `mobile/`，可通过浏览器安装到手机或桌面。
- 微信小程序位于 `mobile/miniprogram/`，包含首页、记录、注册和我的页面。
- 小程序首页支持管理员/用户两种登录模式。
- 真机上线需要 AppID、HTTPS 域名和合法服务器域名配置。

## 5. 场景选型

| 场景 | 推荐模式 | 拓扑 |
|---|---|---|
| 单门、单办公室、无网络环境 | 离线局域网 | 集成 |
| 工厂/园区多门禁，内网统一管理 | 在线局域网或离线可降级 | 分离 |
| 手机远程查看、员工自助查询 | 在线公网 | 分离 |
| 临时演示或开发测试 | 离线局域网 + 仿真硬件 | 集成 |
| 多分支、多地点统一审计 | 在线公网 + 边缘缓存 | 分离 |

## 6. 生产上线检查清单

- [ ] 已替换默认 Web token、HMAC secret 和管理员 PIN。
- [ ] 公网模式已启用 HTTPS，并配置 CORS 白名单。
- [ ] `python deployment.py` 输出 `ok=true`。
- [ ] 全量测试通过，`pip check` 无依赖冲突。
- [ ] 硬件模式、串口参数、继电器命令和接线已真机验证。
- [ ] 门磁、出门按钮、报警器、电锁和电源完成现场测试。
- [ ] 离线断网、恢复同步、断电重启和长时间运行已验证。
- [ ] 真实采集设备和人员数据已完成 FAR/FRR/EER 等指标评估。
- [ ] 小程序 AppID、HTTPS 域名和备案/合规要求已确认。

## 7. 能力边界

- 合成数据验证只能证明软件链路可运行，不能代表真实硬件精度。
- 启发式活体不能替代专用 PAD 模型或双目/3D 防伪设备。
- 仿真继电器不会产生真实开门动作，生产必须切换并验证真实硬件。
- Docker 镜像构建、公网证书、小程序真机和具体厂商 SDK 需要在对应环境中验收。
- 涉及消防门、强电接线和现场安装时，应由具备资质的人员实施。
