# 原始采集样本与模板版本管理

本文说明人脸、指纹、虹膜、掌纹、静脉、声纹、步态、视网膜和签名等原始采集样本的加密保存、版本游标、覆盖留痕和回退机制。

## 1. 设计原则

系统同时保存两类数据：

1. **原始采集样本**：例如人脸图片、指纹图片、虹膜图片、音频、视频或签名轨迹。
2. **提取后的生物特征**：由模型或厂商 SDK 生成的模板，用于识别和比对。

默认安全策略：

- 原始样本和模板均加密后落盘。
- 展示给用户或管理员的是可理解的录入图片、音频或视频。
- 识别链路调用的是提取后的模板，不直接依赖原图。
- 缺少加密密钥时拒绝写入，不允许静默明文保存。
- 重复录入采用覆盖应用，但保留上一版用于审计和回退。

## 2. 版本游标

每个人员、模态、设备组合使用两个版本号：

- `0`：上一版本
- `1`：当前应用版本，默认激活

### 首次录入

第一次录入时只有版本 1：

| 版本 | 状态 | 内容 |
|---|---|---|
| 0 | 不存在 | 为空 |
| 1 | 激活 | 本次原图和特征 |

### 第二次录入

再次录入后：

| 版本 | 状态 | 内容 |
|---|---|---|
| 0 | 归档 | 上一次原图和特征 |
| 1 | 激活 | 本次原图和特征 |

### 回退

执行回退时，不删除版本 1，只切换激活游标：

| 版本 | 回退前 | 回退后 |
|---|---|---|
| 0 | 归档 | 激活 |
| 1 | 激活 | 归档 |

### 回退后重新录入

如果当前激活的是版本 0，重新录入时：

- 当前激活版本 0 成为新的上一版本；
- 新录入内容成为版本 1；
- 原来归档的版本 1 会被覆盖清理；
- 始终只保留最近两个版本。

## 3. 数据结构

核心实现位于：

- `biometrics/capture_store.py`
- `biometrics/capture_store.CaptureRepository`
- `biometrics/capture_store.CaptureVersion`

每条版本记录包含：

| 字段 | 说明 |
|---|---|
| `subject` | 人员标识 |
| `modality` | 生物识别模态 |
| `device_id` | 来源设备或注册端 |
| `version` | 0 或 1 |
| `is_active` | 是否为当前激活游标 |
| `image` | 加密后的原始样本 |
| `image_mime` | 原始样本类型 |
| `template` | 加密后的特征模板 |
| `quality` | 采集质量分 |
| `digest` | 模板完整性摘要 |
| `meta` | 非敏感辅助信息 |
| `created_at/updated_at` | 创建和更新时间 |

## 4. API

多模态 Web API 已提供采集版本接口。

### 查询版本

```http
GET /api/biometrics/captures/versions?subject=张三&modality=fingerprint&device_id=WEB
```

### 查看原始样本

```http
GET /api/biometrics/captures/image?subject=张三&modality=fingerprint&device_id=WEB
```

可通过 `version=0` 或 `version=1` 查看指定版本；不传版本时返回当前激活版本。

### 回退版本

```http
POST /api/biometrics/captures/rollback
Content-Type: application/json
Authorization: Bearer <token>

{
  "subject": "张三",
  "modality": "fingerprint",
  "device_id": "WEB"
}
```

## 5. 本地与云端存储建议

生物识别原始样本属于敏感个人信息。直接永久上传云端会提高合规、泄露和越权访问风险，因此推荐采用“边缘加密主存 + 云端可选元数据/备份”的混合方案。

### 默认推荐：本地加密主存

- 原始样本和模板保存在边缘端或本地服务器。
- 数据使用 Fernet 加密。
- 管理端在线时，通过鉴权接口从边缘端读取录入图片。
- 云端默认只保存设备状态、记录摘要、模板摘要或备份索引。

### 可选：云端加密备份

只有在完成单独同意、隐私政策、PIA、访问控制和备份策略后，才启用云端原始样本备份。

要求：

- 传输过程使用 HTTPS。
- 服务端加密存储。
- 管理权限分级。
- 访问行为留日志。
- 支持注销封存和按需调用。
- 明确数据保存地点和保留周期。

## 6. 永久保留与注销封存

系统可设计为永久保留，但“永久保留”应区分正常状态和注销状态。

### 正常状态

用户可查看自己的信息；管理员可按权限查看管理范围内的人员信息。

### 注销、离职、退租

用户账号注销后，原始样本和模板进入注销数据区：

- 正常用户列表不再展示；
- 数据加密封存；
- 保留必要审计记录；
- 仅按授权流程调取；
- 具体留存年限以适用法律法规、行业规定和组织制度为准。

## 7. 合规前提

启用原始样本保存前，应完成：

- 隐私政策和处理规则告知；
- 针对生物识别信息的单独同意；
- 个人信息保护影响评估（PIA）；
- 管理员和普通用户权限隔离；
- 加密、备份、回退、注销封存和审计机制；
- 真实设备和真实人员数据的测试验收。
